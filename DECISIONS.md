# DECISIONS

Deviations from `docs/spec/` are recorded here (File 01 §B). LEAN EDITION precedence applies:
LEAN overrides Files 01–02; File 03 adds binding detail.

| ID | Decision | Reason |
|---|---|---|
| D-13 | The later-phase scripts named in the P0.1 tree (`scripts/gen_tokens.py`, `check_contrast.py`, `seed_demo.py`, `virtual_child.py`, `smoke_prod.py`) are created in Phase 0 as honest stubs that print their owning slice and exit 1; each is fully implemented by its owning slice (P1.3, P1.3, P2.8, P2.8, P7.4). | Gate-0's layout check requires every P0.1 path to exist, while G4/G5 forbid empty fakes; a stub that loudly fails is honest, and no gate invokes these before their phase. |
| D-14 | Repo root is this workspace directory (it already contained `docs/spec/`); the `senseheaven/` name in the P0.1 tree refers to the repository itself, not a subdirectory. | The build starts "from an empty directory" — this one. |
| D-15 | A foreign container `sensehaven_db` (postgres:16-alpine, created 2026-09-15, restart=unless-stopped) from an unrelated prior project was **stopped** with its restart policy disabled — not deleted — to free host port 5432 for this project's compose `db`. | It auto-started with the colima VM and blocked `docker compose up -d db` (gate-0 failure cycle 2). The container predates this build, so it is preserved for its owner. |
| D-16 | In development/test, missing `DATABASE_URL`/`APP_SECRET`/`PAIRING_PEPPER` fall back to documented dev defaults (compose DB URL, fixed dev secret) with a stderr warning; production still fails fast per P2.1. | Keeps `make up` and tests working from a fresh clone without a human step; secrets remain env-only in production (G8). |
| D-17 | `screen_sessions.status` gains `pending` on top of File 01's enum, per the File 03 binding ("creates a session with status **pending**"). | Parent-initiated sessions start before the device picks up the `start_session` command. |
| D-18 | "Wrong code increments attempts" is implemented as: a pair attempt whose code hash matches a *known but unusable* row (used / expired / attempts-exhausted) increments that row's `attempts` and returns 410; a hash with no row returns 422 `PAIRING_CODE_INVALID` and is bounded by the 10/hour/IP pair limiter. | A hash miss cannot be attributed to any row; the IP limiter covers brute force, so the security property (≤ 5 usable attempts per code) holds. |
| D-20 | GuardService holds a `PARTIAL_WAKE_LOCK` (6 h hard cap) and the manifest gains `WAKE_LOCK` — outside the File 01 permission allowlist, logged here as a deviation. | The engine's cooldown timer and the 10–15 s sync cadence must progress while the screen is off (E6-1 offline behaviour); without the lock the CPU sleeps and the countdown stalls. Battery cost is accepted for the demo scope and listed in the model card's limitations. |
| D-19 | Pairing a new device for a child revokes the child's previous device (File 03 binding; refines File 01 D-10's one-device rule). | One active device per child keeps session ownership unambiguous; revoked devices get `401 DEVICE_REVOKED` and wipe locally. |
